# Ingest Profile Contract

Status: **fixed v0.1 (2026-07-28; v0 fixed 2026-07-25)**. This contract governs
E-4a stage 1. Fixing the contract does not admit the profile;
`admission = "off"` remains in force.

## 1. スコープ

第1段の対象は、ローカルに保存済みのHTMLまたはテキストのソース
スナップショットから、goalで宣言されたレコード形式へ抽出・整形する
単発パイプラインの生成である。

入力は `data/snapshots/` 配下の1つ以上のファイルと、goal内で宣言された
出力フィールド・型・必須性である。納品物は再実行可能な
`pipeline/main.py`、機械可読出力 `output/records.json`、人間可読の
`output/report.md` とする。

ネットワークからの取得とその鮮度検証は第2段の fetch probe として
**QUEUED** であり、本draftの実装・計測対象には含めない。

## 2. full の意味（最重要・不変条件）

fullとは「パイプラインが実行され、出力レコードの全フィールド値が
ソーススナップショット内の実在断片に機械照合で束縛され、候補単位の
勘定（検出 = 採用 + 理由別除外）が整合し、宣言フォーマットに準拠し、
再実行で同一結果が得られた」ことを意味する。

fullはソース内の全イベントを発見したこと、ソースが最新であること、
または取得元に存在する全イベントを取得したことを意味しない。

## 3. 要求 evidence（full の必須ゲート）

N1 `ingest_probe`:
`pipeline/main.py`を隔離・有界で実実行し、exit、stdout、stderr、入力と
成果物の識別子を `evidence/ingest-probe.json` に記録する。正常終了と
3つの納品物の実在が必要である。実行機構は既存pipeline probeを流用する。

N2 `source_binding`:
各出力レコードの全フィールド値を、次の3つの束縛域のいずれかへ機械照合
する。

1. そのレコードが由来する同一候補ブロック内の実在断片。
2. 同一候補ブロック内の実在断片に対する宣言済みの値保存形式変換。
3. **文書共有文脈（document-level shared context）**を用いた部分値の
   補完。ページタイトル、候補外の文書見出し等の文書レベル情報から年等を
   補い、候補内`8/3`と文書文脈`2026年`から`2026-08-03`を得る形をいう。

第3域は、(a) 値保存の合成であること、(b) 補完規則がフィールドごとに
決定的に宣言されること、(c) evidenceに候補ブロック内断片と文書文脈断片の
**両方**を、各スナップショット相対パス・byte位置・変換過程つきで記録する
こと、の全条件を満たす場合だけ許可する。候補ブロック内に年を含まない
`8/3`と文書見出しの`2026年`の合成は値保存だが、`8/3`から`8/4`への変更は
値保存ではない。別候補の年・名称・場所等を流用する候補間の継ぎ合わせは
文書共有文脈ではなく、従来どおり禁止する。文書内のどこにも実在しない値も
従来どおり違反である。

evidenceにはレコード・フィールドごとにスナップショット相対パス、候補
識別子、ソース断片、位置、比較結果、許可された正準化過程、
`nearest_miss`を記録する。許可する正準化はHTML entityの復号、改行・空白の
決定的な正準化など値を変えない処理を認める。加えて、値を保存する形式変換
（和暦・日本語日付表記からISO日付、数値の桁区切り・全角数字の正規化、
時刻表記の24時間化等）は、変換規則が決定的に宣言され、フィールドごとの
変換過程がevidenceに記録される場合に限り許可する。値の変更（日付のずれ・
数量の改変）は形式変換と区別し、名称の言い換え、候補間の値の継ぎ合わせと
ともに認めない。存在しないイベントの捏造またはフィールド値の改変は従来
どおり`source_binding_violation`としてfailする。出力レコードが0件なら
N2は`claims_absent`であり、passまたはfullとして扱わない。

N3 `accounting`:
inspectionで宣言された決定的セレクタにより、入力スナップショットから
候補ブロックを機械列挙する。セレクタと列挙済み候補集合はパイプライン
実行前に凍結し、候補総数について
`detected = accepted + sum(excluded_by_reason)`を要求する。各除外は候補
識別子と理由を持ち、無申告の欠落を認めない。実行後のセレクタ変更、
候補集合の縮小または置換は`candidate_set_violation`としてfailする。

N4 `format_schema`:
`output/records.json`が、実行前にgoalから束縛した宣言フォーマットの
フィールド名、必須性、型およびトップレベル形状に準拠することを
`evidence/format-schema.json`へ記録する。判定機構はdata profileの
E4 schema assertionを流用する。スキーマ外フィールド、必須フィールド
欠落、型違反はfailする。

N5 `rerun`:
凍結済みの同一スナップショット、宣言フォーマットおよび候補セレクタで
パイプラインを再実行し、`output/records.json`と`output/report.md`の
結果が初回と同一であることを`evidence/rerun-consistency.json`へ記録
する。判定機構はdata profileのE3を流用する。

## 4. assurance 階層

- `full`: N1〜N5がすべて実行され、すべてpassする。
- `partial`: N1がpassし、N2が実行済みの`claims_absent`であり、N3〜N5に
  failureがない。出力レコード0件から`full`は獲得できない。
- `static`: N1が未実行である。生成物や静的検査だけでは昇格できない。
- `failed`: N1の実行失敗、N2の捏造・値改変、N3の勘定不整合または候補
  集合違反、N4のスキーマ違反、N5の再実行不一致のいずれか。`failed`は
  `partial`より優先する。

profileがdraftである間は、N1〜N5がfull相当でも共通admission gateにより
外部表示のassuranceは`static / profile_not_admitted`を上限とする。

## 5. 実行プローブ

プローブは生成過程やモデルの説明を裁定材料にせず、凍結済み入力、
inspection、納品物だけを観測する。ワークスペース限定・ネットワーク
遮断・タイムアウト有界の子プロセスでN1を実行し、N2〜N4を評価した後、
同じ条件でN5を実行する。stdout/stderrは有界に保存し、各evidence JSONは
入力識別子、初回実行、再実行、候補集合のlineageを相互参照できなければ
ならない。

## 6. 偽装耐性（conformanceネガティブテストの要求）

1. ソースに存在しないレコードを出力した成果物をN2で拒否する。
2. 日付ずらし等、ソース断片からフィールド値を改変した成果物をN2で
   拒否する。
3. 検出候補を採用にも理由別除外にも計上しない成果物をN3で拒否する。
4. 宣言フォーマット外または型違反の出力をN4で拒否する。
5. N1未実行のevidenceから`partial`または`full`を獲得できない。
6. 凍結後に候補単位セレクタまたは候補集合を縮小・置換したevidenceを
   N3で拒否する。

## 7. スコープ外（明示）

本profileは**網羅性（取りこぼしゼロ）を保証しない**。保証するのは
出力されたレコードと全フィールド値が実在断片に束縛されること、および
宣言した決定的セレクタで機械列挙できる候補の勘定が閉じることだけで
ある。セレクタがソース内の全イベントを発見するかという意味論的完全性
は、いかなるassurance階層でも主張しない。

JavaScript等による動的レンダリング、認証、ページ遷移、取得元全体に
対する網羅性は本profileの恒久スコープ外とする。ソースの鮮度と
ネットワーク取得は第1段のスコープ外であり、第2段のfetch probeとして
QUEUEDである。

## 8. 生成側への制約

入力スナップショットは固定し、生成パイプラインからのネットワーク通信を
禁止する。時刻、乱数、外部状態、非決定的な列挙順に依存せず、レコードと
理由別除外を安定順で出力する。

候補単位セレクタはinspectionへ明示し、N1の実行前に凍結する。goal由来の
宣言フォーマットも実行前に束縛し、実行結果に合わせたフィールド・型・
候補集合の事後変更を禁止する。
