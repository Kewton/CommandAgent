## Review refinements

The canonical origin hook lives in `runner/phase/recovery_authority::begin`, after UltraPlan lint, so `phase/flow.rs` stays unchanged at its growth ceiling. The transaction writes a new host-owned, read-only `inspection-context.json` under the existing treatment runtime directory. No live `.anvil` migration is involved.

`AttemptCapture` retains both original intent and a validated context on each recover execution. A continuation candidate carries that context to the next transaction even if its driver still uses the original workspace. The contract hash must agree before inheritance. Original goal and diagnostics remain alongside continuation evidence; source ranges are recomputed in the new treatment.

Missing new provenance is distinct from invalid provenance. Manual `recover` YAML, unsupported intents, and old fix-origin-only runs receive no new context and retain the old start/binding behavior. Existing fix evidence still validates and binds normally. Absent completion contracts or empty registered commands grant no new binding; malformed context and contract mismatch return errors. No create intent is inferred from absence.

Read ranges cover contiguous source sections with breaks at exports and compact character budgets. Member's fields, including line 8 `role: string`, are retained; long store functions span multiple windows. Tests execute the generated ranges through the real tool/message path, accounting for its 500-character result summary. Long diagnostic instructions are split into read-only steps within the existing 2,500-character / 12-step lint limits rather than truncating diagnostics or raising those limits.

The related-import resolver supports JS/TS (`js`, `jsx`, `ts`, `tsx`) only. The new exhaustive read set is enabled only when all validated existing repair targets use those extensions; denied paths cannot disable the restriction. Missing targets or any other language retain the existing workspace read policy while receiving provenance, diagnostic retention and read-only phase binding. Listed paths are then starting points, so Python `from helper import f` and Rust `mod helper` can lead to additional Read calls. An unscoped continuation cannot gain the JS/TS read restriction from a later diagnostic. No Python/Rust parser is introduced. Production-driver regression replays both languages for create/fix, reads the unlisted helper, rejects inspect mutation, and reaches repair. Workspace/private Read and protected Edit rejection are checked separately through the actual tool registry because external-read violations terminate the existing step; legacy read permissions are preserved.

Required non-text assets remain in the completion contract without contributing textual Read suggestions. A binary asset in the language regression reproduced a treatment-binding failure before this refinement; skipping its text ranges preserves existing Recovery startup and all final verification requirements.
