## Postclosure diagnosis and controls

Command diagnoses pair exact strings with evidence kind, weakness reason,
repairability and observed execution failure. They are additive fields on final
acceptance and Recovery observations; original event names/schema fields remain.
Recovery admission stops a fixed inline evidence blocker before app-owner
execution. Confirmation rejects pending/discharge for known immutable inline or
frozen-script Weak evidence when the existing contract evidence gate requires
it. Contract bytes/hash and verifier preservation checks remain authoritative.
The final-acceptance event corpus key list adds only `command_diagnoses`; the
exact-key assertion still protects every existing field. Its first full-suite
failure and corrected passing rerun are recorded separately in verification.

Evidence quality and execution failure stay distinct. Postclosure control reuses
the existing `source_first_completion_authority_required` predicate; a runtime-only
legacy/configured contract does not gain a new quality gate. The actual #465
configuration-wrapper regression keeps its original related-store success and
ignoreBuildErrors-bypass rejection without changing its fixture or assertions.
Missing scripts receive no write authority from diagnosis; only the existing
registered producer path permits creation. Existing Test runtime failures remain
input-dependent. Normal source change → pending → later owner → confirmation,
no-op/unrelated edit refusal and processing-loss refusal remain covered.

A shared bounded Node argv discriminator covers separate/equals/glued inline
forms. Actual Node v24.1.0 executes `--eval=...`, rejects glued short forms with
exit 9, and does not execute `--print=`'s value. The latter forms cannot gain Test
credit from an unexecuted assertion. Shell expansion/compound ambiguity remains
conservative. Rust CI declares Node v24.1.0 for reproducible saved-module tests.

## Changed code and limits

Behavior lives in the `import_check`, `structural_checks`, `command_diagnosis`
and `verifier_formation` leaves, with small wiring in admission, Recovery
confirmation and final acceptance. No driver/loop growth-baseline change,
knowledge manifest change, contract migration, new runtime budget or historical
evidence rewrite was made. The new source-only corpus contains copied module
and package bytes, command lists and driven refusal cases.

The grammar is intentionally limited; unsupported proposals exhaust honestly.
Classifier recognition never proves execution success. The bounded product
diagnostic can summarize an ESM thrown error as a compile error; raw-execution
controls separately verify original rejection propagation. This is not a claim
to fix #480's independent diagnostic attribution issue.

Parent-owned review, exact-commit UAT/CI, integration/release and live evaluation
remain separate gates. No push, PR, Issue mutation, CommandMate operation, live
model call or observer/campaign modification was performed.
