RAW PROPOSAL CONTRACT:

- With `required_claims`, emit every supplied `claim.id` exactly once and no
  others. Without it, create unique temporary IDs for atomic claims.
- A raw claim contains `id`, `normalized_requirement`, `kind`, and optionally
  one allowed `unverifiable_reason`. Do not emit `origin`, byte range, required,
  or oracle IDs; all are host-owned.
- A raw oracle contains `claim_id`, strategy, expected polarity, minimum
  strength, setup, input, observation, and timeout. Do not emit host-owned ID,
  observed strength, lifecycle, result, lineage, or provenance.
- Operational constraints and completion paths/commands may bind an oracle to
  an existing claim. They are not claims and do not prove execution or success.
- Use only paths and bindings present in `workspace_manifest`.

SEMANTIC CAPABILITY POLICY:

- `semantic_policy_sha256` identifies the host policy used again before
  execution and scoring. Do not reinterpret or bypass it.
- In conformance, emit an oracle only from that claim's non-empty
  `expected_observations` and only when `executor_status` is `available`.
- In held-out synthesis, use only strategies listed in
  `executor_capabilities.strategies`. Workspace files, task commands, or an

- If no visible capability can meaningfully observe a claim, preserve the claim
  without an oracle and use exactly one of `executor_capability_unavailable`,
  `safe_execution_unavailable`, or `workspace_binding_unavailable`. This is
  unverified, never pass.
- An executable command is not automatically semantically sufficient. Its
  observation must directly establish the claim. Never use a source literal as
  proof of network activity or absence, or a generic artifact-exists check as
  proof of causal intervention, timeout boundaries, source location, or a
  reproducer outcome.
- Do not use honest unknown when a listed capability, exact visible argv, and
